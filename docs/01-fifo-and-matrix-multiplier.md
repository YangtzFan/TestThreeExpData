# 01：同步 FIFO 与矩阵乘法器的 RTL 原理

这两个模块都在时钟上升沿更新寄存器。读代码时，先问两个问题：**沿到来之前，输入经过了哪些组合逻辑？沿到来时，哪些值会被保存下来？** FIFO 保存还没读走的数据；矩阵乘法器保存本次输入算出的结果。

## 1. SimpleFifo：用四个格子实现先进先出

对应源码：[simple_fifo.sv](../modules/fifo/rtl/simple_fifo.sv)。模块固定有 4 个存储槽，每槽 8 位，读写共用 `clock`。

把 `mem[0]` 到 `mem[3]` 想成一圈格子。`wr_ptr` 指向下一次写入的位置，`rd_ptr` 指向最早写入且还没读走的数据。两个指针都是 2 位，所以 `3 + 1` 截断后自然回到 `0`。只看指针不够：复位后两个指针都为 `0`，连续写满四格后也都为 `0`。因此 RTL 另外用 `count` 记录占用量，区分空和满。`count` 要表示 `0` 到 `4`，需要 3 位。

### 什么时候真正读写？

| 方向 | FIFO 给出的信号 | 上升沿实际发生的操作 |
| --- | --- | --- |
| 写入 | `wr_ready = (count < 4)`：还有空格 | `wr_valid && wr_ready` 为真时，把 `wr_data` 写入 `mem[wr_ptr]`，然后推进 `wr_ptr` |
| 读出 | `rd_valid = (count != 0)`：队头有数据 | `rd_valid && rd_ready` 为真时，接收方取走当前 `rd_data`，FIFO 推进 `rd_ptr` |

这两项操作都在复位未置位的上升沿发生。`rd_data` 则一直由组合逻辑驱动，等于 `mem[rd_ptr]`。因此，只要 FIFO 非空，队头数据在读握手的上升沿**之前**就已出现在端口上；握手后读指针前进，端口随之指向新队头。单有 `rd_valid` 不会弹出数据，接收方还要给出 `rd_ready`。

### 跟着时钟走四步

下表每行代表一个上升沿，逻辑队列把最早写入的数据放在左边。

| 沿前队列 | 这个沿的请求 | 实际读出 | 沿后队列 | `count` 变化 |
| --- | --- | --- | --- | --- |
| `[]` | 写 `0x12`，同时请求读 | 无：沿前为空 | `[0x12]` | `0 → 1` |
| `[0x12]` | 写 `0x34` | 无 | `[0x12, 0x34]` | `1 → 2` |
| `[0x12, 0x34]` | 写 `0x56`，同时请求读 | `0x12` | `[0x34, 0x56]` | `2 → 2` |
| `[0x34, 0x56]` | 请求读 | `0x34` | `[0x56]` | `2 → 1` |

第三行说明为什么同时读写时两个指针都前进，但 `count` 不变：增加一个元素，同时移走一个元素。RTL 用 `case ({do_push, do_pop})` 统一更新计数：只写加一、只读减一，其余保持原值。

第一行也说明了这个实现的边界：**空时不能在同一个沿把刚写入的数据直接交给读端**。同理，沿前若已满，即使同一沿会读出一个元素，写端也得等下一拍才会看到 `wr_ready=1`。这是因为 `wr_ready` 和 `rd_valid` 都只由沿前的 `count` 决定。

`reset` 为高时，在上升沿清零 `count` 和两个指针。RTL 没有清空 `mem`；队列是否有有效数据由 `rd_valid` 判断，因此在 FIFO 为空时不应使用 `rd_data`。

## 2. matrix_multiplier：把行和列做点积

对应源码：[matrix_multiplier.sv](../modules/matrix_multiplier/rtl/matrix_multiplier.sv)。设输入矩阵为 `A[M×K]` 和 `B[K×N]`，结果为 `C[M×N]`。`M`、`K`、`N` 分别对应 `A_ROWS`、`A_COLUMNS_B_ROWS`、`B_COLUMNS`，默认是 `10`、`6`、`4`。

计算 `C[i,j]` 时，取 `A` 的第 `i` 行和 `B` 的第 `j` 列，把对应元素相乘，再把这 `K` 个乘积加起来：

```text
C[i,j] = Σ A[i,k] × B[k,j]，其中 k = 0, …, K-1
```

这里 `K` 既是 `A` 一行的长度，也是 `B` 一列的长度，两边必须一样长。

### 一维端口如何表示矩阵？

RTL 用一维数组传输矩阵，顺序是**先放完整的第 0 行，再放第 1 行**，依此类推。从 0 开始编号时，找到第 `r` 行第 `c` 列的方法是 `r × 每行元素数 + c`。

| 元素 | RTL 索引 | 为什么乘这个数？ |
| --- | --- | --- |
| `A[i,k]` | `a_i[i*K + k]` | `A` 每行有 `K` 个元素 |
| `B[k,j]` | `b_i[k*N + j]` | `B` 每行有 `N` 个元素 |
| `C[i,j]` | `c_calc[i*N + j]`，寄存后为 `c_o[i*N + j]` | `C` 每行有 `N` 个元素 |

例如，取 `M=2`、`K=3`、`N=2`：

```text
A = [1 2 3]      B = [ 7  8]
    [4 5 6]          [ 9 10]
                     [11 12]
```

`a_i = [1, 2, 3, 4, 5, 6]`，`b_i = [7, 8, 9, 10, 11, 12]`。计算 `C[0,1]` 时，取 `a_i[0]`、`a_i[1]`、`a_i[2]` 和 `b_i[1]`、`b_i[3]`、`b_i[5]`：

```text
C[0,1] = 1×8 + 2×10 + 3×12 = 64
C      = [ 58  64]
         [139 154]
```

所以端口上的结果按 `[58, 64, 139, 154]` 排列。注意取 `B` 的一列时，索引每次跨过 `N` 个位置。

### 组合计算与输出寄存

`always @(*)` 中的三层循环对应 `i`（结果行）、`j`（结果列）、`k`（点积项）。每计算一个新的 `C[i,j]`，先把临时变量 `c_element` 清零，再用阻塞赋值 `=` 累加乘积，最后把结果写到 `c_calc` 的对应位置。这些循环描述的是组合逻辑：**`k` 每增加一次，不意味着经过一个时钟周期**。默认参数下，一次计算包含 40 个点积、共 240 项乘积；实际资源与关键路径由综合结果决定。

`always @(posedge clk_i)` 负责把整个 `c_calc` 和 `valid_i` 寄存到输出。若输入矩阵和 `valid_i=1` 在某个上升沿之前已稳定，那么该沿之后，`c_o` 给出这组矩阵的结果，`valid_o=1`。`valid_i=0` 时，`c_o` 仍会更新，但 `valid_o=0`，接收方应忽略这个结果。模块没有 `ready` 信号；在满足时序要求时，每个上升沿都可以采样一组新矩阵。`reset_i=1` 时，上升沿会把 `valid_o` 和 `c_o` 清零。

### 为什么结果比输入宽？

端口元素是无符号数。两个 `W` 位数相乘，单项乘积最多需要 `2W` 位。一个点积要加上 `K` 个这样的乘积，因此默认再留 `ceil(log2(K))` 位容纳加法进位，前提是 `K ≥ 1`。RTL 中的 `C_DATA_WIDTH = 2 * DATA_WIDTH + $clog2(A_COLUMNS_B_ROWS)` 就是这个位宽上界。以默认参数为例，单项乘积最多需要 64 位，6 项求和再留 3 位，所以结果元素默认是 67 位。手动把 `C_DATA_WIDTH` 改小会减少累加和输出能保留的位数，较大的结果可能被截断。
